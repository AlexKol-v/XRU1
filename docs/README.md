# XRU1 «Тихий узел» — документация

Курсовой прототип пошаговой тактики в духе XCOM 2 на UE 5.7: укрытия, очки
действий, наблюдение, отряд из четырёх классов. Демо — меню → хаб → обучение →
боевая миссия → финальный экран.

> **Источник истины — код, ассеты и git.** Эти документы объясняют, **как
> устроено и почему принято именно так**. При расхождении с кодом прав код;
> расхождение чинится в доке, а не в коде «под доку».

## Состояние проекта

Демо собрано и проходится от главного меню до финального экрана: аттестация на
полигоне «Купол» (четыре секции с озвучкой и подсказками) и боевая миссия
«Узел-7» с заряд-таймером, подкреплениями и эвакуацией. Обе миссии играются на
одной карте `Main_Map_Showreel` разными streaming sublevel; текст игры собран в
цель локализации `Game` и переведён на английский целиком.

Принятые дизайнерские развилки с рассмотренными альтернативами и осознанно
снятое с плана — [01_GDD.md](01_GDD.md) §14. Рабочий список задач и матрица
ручной приёмки ведутся вне сдаваемой документации.

## Куда проект развивается дальше

Не обязательства, а осознанный план на случай продолжения:

- **экран загрузки миссии** — старт боя ждёт готовности навигации, и эта пауза
  видима игроку; закрывается полноэкранным виджетом по факту готовности;
- **полировка HUD** — названия способностей на кнопках вместо родового текста,
  причина недоступного действия рядом с кнопкой, секционный HP в карточке отряда;
- **функциональные тесты тумана войны** — сейчас автотестами закрыт только
  скоринг AI (`XRU1.AI.*`, 7 тестов);
- **анимационный слой** — Aim Offset и IK второй руки на цевьё; оба косметические
  и по построению не трогают боевой поток;
- **окружение** — PCG-раскладка декора поверх ручной расстановки укрытий.

## Как работать с документацией

1. Перед задачей: [01_GDD.md](01_GDD.md) — какие правила. Меняешь механику
   вопреки GDD — сначала правь GDD.
2. Перед C++-работой: [03_ARCHITECTURE.md](03_ARCHITECTURE.md); по AI —
   [04_AI.md](04_AI.md). Там же особенности UE, о которые проект уже спотыкался.
3. После реализации: синхронизируй доки — архитектуру при изменении устройства,
   GDD при изменении правил.
4. Не заводить новый audit/checklist-файл ради единичного бага.
5. История миграции из донора — вне `docs/`, в [../MIGRATION_NOTES.md](../MIGRATION_NOTES.md).
   Журналы прошлых сессий не восстанавливать: они целиком в `git log`.

## Быстрый старт на второй машине

```powershell
git pull
git lfs pull
.\Build-XRU1.ps1
```

Редактор перед сборкой должен быть закрыт; пути не хардкодить — `Build-XRU1.ps1`
находит UE 5.7 через реестр. Подробности — [05_WORKFLOW.md](05_WORKFLOW.md) §1.
