### E1.5 ШАГ 6 — Стейт-машина «Поза»

⚠️ **«Вжаться в высокое укрытие» отдельной анимацией НЕ делаем** (решение
2026-07-25). Вместо неё C++ по прибытии зовёт `AUnitBase::HugCover()`: юнит
разворачивается **лицом к стене по её нормали** и подтягивается к ней
вплотную. Поза за укрытием читается сама, если боец стоит вплотную и лицом к
стене, — набор cover-анимаций для этого не нужен.

| Состояние | Анимация | Переход по |
|---|---|---|
| `Idle` | `MF_Rifle_Idle_ADS` | `Pose == Stand` |
| `Locomotion` | `BS_Rifle_Locomotion` по `Speed`+`Direction` | `Pose == Moving` |
| `CrouchCover` | **`anim_CoverDown_Idle_Left/Right`** (вход, один раз) → автопереход в **`anim_CoverDown_Loop_Left/Right`** (устойчивый цикл), по знаку `CoverSideY` | `Pose == CrouchCover` |
| `HighCover` | та же пара Idle→Loop (юнит уже прижат и развёрнут кодом) | `Pose == HighCover` |
| `Overwatch` | `MF_Rifle_Idle_ADS` + Aim Offset вверх | `Pose == Overwatch` |
| `Hunkered` | `BS_Crouch` (см. E1.4 — весь директориальный набор, не только Idle) | `Pose == Hunkered` |
| `Downed` | **`anim_Downed_Idle_R`** (луп) | `Pose == Downed` |
| `Dead` | `MM_Death_Front_01`, последний кадр | `Pose == Dead` |
| `Jump`/`Fall`/`Land` | `Rifle/Jump/*` (см. E1.4) | стандартный переход CMC (`IsFalling`) |

⚠️ **Выбор стороны прижимания — по `CoverSideY`.** Это `VisualState.CoverDirectionLocal.Y`
(стена в осях юнита): `> 0` → стена справа → `anim_CoverDown_Idle_Right`,
`< 0` → `_Left`. Ровно ради этого поле и считается в C++.

⭐ **`CrouchCover`/`HighCover` — пара анимаций, не одна.** `anim_CoverDown_Idle_*`
не зациклена — это «заселение» в позу. По окончании стейт-машина сама
переходит на `anim_CoverDown_Loop_*` (уже зациклен) — устойчивое ожидание.
Раньше в этой ячейке стояла только `Idle` без продолжения, и `Loop_*`
(2 готовых ассета) не использовался нигде.

⭐ **`anim_CoverDown_Look_Left/Right` — обязательный шаг, не опция.** Раньше
документ называл их украшением «по желанию». По аудиту использования анимаций
(2026-07-26): эти два клипа — единственное, что даёт монтажам выстрела из
укрытия (E1.7) визуальную подготовку «выглянул → выстрелил» вместо мгновенного
щелчка в позу стрельбы. Реализация — не отдельное состояние стейт-машины
(поза укрытия не должна на него переключаться), а **отдельный короткий
монтаж `AM_Peek_Left/Right`**, который BP проигрывает первым в `OnShotFired`
перед основным монтажом выстрела — см. E1.7/E1.8.

💡 **Опционально, но по духу задачи «использовать всё» — доворот на месте.**
8 анимаций `Crouch/M_Neutral_Crouch_Idle_Turn_045/090/135/180_L/R` пока нигде
не подключены — это анимации доворота юнита без смены клетки (например, цель
сменилась, а укрытие и позиция те же). Готового C++-поля под это нет
(`FUnitVisualState` не хранит дельту поворота), но подключить можно **чисто
в BP**, без правок C++:
- в `Event Blueprint Update Animation` сравнить `GetActorRotation().Yaw`
  текущего кадра с прошлым (переменная-кэш) → получить `DeltaYaw` за кадр;
- если `|DeltaYaw|` за один «тик» довора превышает порог (юнит не идёт, просто
  разворачивается на месте) — определить бакет 45/90/135/180 по модулю и
  сторону (`L`/`R`) по знаку `DeltaYaw`;
- проиграть соответствующий `M_Neutral_Crouch_Idle_Turn_*` как короткий
  переходный монтаж/blend, только в состояниях `Hunkered`/`CrouchCover`/
  `Overwatch` (стоя на месте — доворот не нужен, там читается по локомоции).

- [ ] Собрать машину, переходы — по одной переменной `Pose`.
- [ ] Blend time между позами 0.15–0.25 с.
- [ ] Aim Offset из `MM_Rifle_Idle_ADS_AO_CU/CD/CC` поверх (по питчу к цели).
- [ ] `CrouchCover`/`HighCover`: Idle → автопереход в Loop настроен (не
      зависает на первом кадре Idle, не остаётся зацикленным на нём).

### E1.8 Запуск монтажей и выбег на пик — из BP юнита

- [ ] `OnShotFired(Target)`:
      1. `GetFireMontageFor(Target)` → даёт монтаж, `OutStance`, `OutFiringEyeLocation`.
      2. ⭐ **Если текущая `Pose` (последний `VisualState`) — `CrouchCover` или
         `HighCover`:** сначала `Play Anim Montage(AM_Peek_Left/Right)` по
         знаку `CoverSideY` **и дождаться его окончания** (`On Completed`/
         `On Blend Out`), только потом переходить к шагу 3. Для `Stand`/
         `Overwatch` этот шаг пропускается — выглядывать не из чего.
      3. Если `OutStance == StepOut`: `AI Move To` в `OutFiringEyeLocation`
         (спроецированную на пол) → по прибытии `Face Actor Towards` цели →
         `Play Anim Montage` (сам выстрел) → по окончании `AI Move To` обратно
         в исходную точку → `HugCover()`.
      4. Иначе просто `Play Anim Montage` выстрела (стойка уже верная).
- [ ] `OnReactionShot(Target, bHit)` → то же самое (включая шаг Peek).
- [ ] `OnDied` → `DeathMontage` (случайный из 6, см. E1.7).

### E1.9 Разное оружие у классов (автомат / снайперка)

**Ответ: да, потому что анимация не знает про оружие.** Rifle-набор — это поза
рук «держу длинноствол»; и автомат, и снайперка держатся одинаково. Меняется
только МЕШ в сокете `hand_r`.

- [ ] Один `ABP_Solider` на всех. Разное оружие = разный меш в `BP_Unit_*`.
- [ ] Если захочется отличать визуально сильнее — добавить в ABP переменную

      нужно**: на тактической камере разницы стойки не видно, а лишний набор
      анимаций надо где-то взять.
- [ ] **Стакинг с приседом работает сам:** присед — это ПОЗА (стейт-машина),

      поверх текущей позы, поэтому «выстрел из приседа» получается без
      отдельной анимации. Если верх тела в приседе выглядит криво — сделать
