# Актуальный roadmap XRU1

Обновлено 2026-07-29. Здесь только открытая работа. Закрытые этапы не хранятся
как многосотстрочные чек-листы: их результат зафиксирован кратко в разделе 1 и
в тематических документах.

## 1. Готовая база

Считаются завершёнными:

- C++ тактическое ядро, GAS-способности, AP и ход сторон;
- player/enemy movement на общей маршрутизации;
- Half/Full cover, LOS, flanking, firing positions и occupancy;
- анимации locomotion/cover/peek/StepOut/fire/HitReact/death;
- синхронизация выстрела через montage `FireCommit`;
- разные модели оружия для четырёх классов;
- функциональное ядро HUD и базовая камера;
- AI-профиль DataAsset и воспроизводимый seed, не зависящий от FPS;
- F0 тумана: единый gameplay visibility, безопасные preview/enemy-count API;
- C++-каркас общей карты: scenario DataAsset, GameInstance routing,
  ScenarioDirector, quest-event bridge и tactical quest zone.

Старые PIE-матрицы закрыты. Если проявится регрессия, она становится отдельным
багом с воспроизводимым сценарием, а не возвращает весь этап в работу.

### 4.1 Дефекты текущего F0 (найдены чтением кода 2026-08-03)

- [ ] **F0-1. Ховер не гейтится.** `ATacticalPlayerController::UpdateHoverHighlight`
      подсвечивает скрытого врага custom-depth обводкой, делает его `HoveredUnit`
      и наполняет панель цели. Скрытый враг не должен становиться `NewHovered`.
- [ ] **F0-2. Оверхед-худ врага не гейтится вообще.** Он создаётся в
      `ATDCombatant::SetupUnitHUD` и живёт всегда: единственный владелец
      видимости оверхедов (`ATacticalPlayerController::UpdateSquadOverheadVisibility`)
      управляет только отрядом игрока. HP-бар висит над невидимым врагом.
      Прятать через `SetOverheadHUDVisible` (`SetHiddenInGame` на компоненте, не
      `SetVisibility` — иначе повторится «замерзание» пипсов из v2.8).
- [ ] **F0-3. Нет кэша видимости.** `UFogOfWarSubsystem::GetCurrentlyVisibleEnemies`
      делает `N_отряда × N_врагов` синхронных сферо-свипов на КАЖДЫЙ вызов, а
      зовут её биндинг HUD (`GetVisibleEnemyCount`) и повторяющийся таймер
      `UTacticalHUDWidget::RefreshActiveEnemyCardVisibility`. Нужен кэш +
      `OnActorVisibilityChanged` + событийная инвалидация. Референс цены: у
      Firaxis аналогичный наивный вызов измерен в ~20 мс
      (`X2TacticalVisibilityHelpers::FillPathTileData`).
- [ ] **F0-4. Два источника правды о видимости стороны.**
      `UTacticsCombatStatics::SquadHasLineOfSight` и
      `UFogOfWarSubsystem::IsActorCurrentlyVisible` — две копии одного расчёта
      (жив + 2500 + LOS), отличаются только исключением себя и жёсткой стороной.
      Свести геометрию в один статик `AnyUnitOfSideSees(Side, Target, Exclude)`;
      подсистема остаётся единственной player-facing обёрткой с кэшем (так
      правило «AI не читает fog игрока» не нарушается).
- [ ] **F0-5. Всплывающий статус выдаёт скрытого врага.** Уход врага в Overwatch
      печатает текст через `UCombatFeedbackSubsystem::ShowStatusText` над
      невидимой позицией. Гейт — один, в `PushEntry`, по якорю записи.
- [ ] **F0-6. Звук выдаёт скрытого врага.** Шаги (`UAnimNotify_UnitFootstep`) и

      от невидимого юнита. Гейт — в `AUnitBase::PlayUnitSound`, с белым списком
      событий, которые звучат всегда.
- [ ] **F0-7. Индикатор Squadsight у Осы мёртв.** Условие в
      `UTacticalHUDWidget` (`CanTargetActor(...) && !HasLineOfSight(...)`) стало
      недостижимым после ревизии обнаружения 2026-07-31: `GetTargetStatus` теперь
      требует геометрический LOS всегда. Кнопка серая навсегда. Правильный

## 5.6. Визуал выстрела (VFX)

Слой построен зеркально звуковому: «когда рисуем» решает C++ на подтверждённом
`FireCommit`, «что рисуем» — `UUnitVfxDataAsset` (вспышка, трассер, попадания по
`EPhysicalSurface`, разброс промаха). Ассеты — из бесплатного `Niagara Examples
Pack` (Epic, UE 5.7), скопирован из учебного проекта в `/Game/NiagaraExamples`
(только замыкание зависимостей `FX_Weapons`, 87 файлов).

- [x] `UUnitVfxDataAsset` + `AUnitBase::PlayShotVfx` рядом с `PlayUnitSound(Fire)`
      в `UGA_Attack` и `UGA_Overwatch`; промах уводится в сторону (`MissSpread`).
- [x] `DA_UnitVfx_Default` (NS_MuzzleFlash, NS_BulletTracer, импакты
      бетон/металл) назначен всем пяти BP юнитов.
- [x] Трассер летит актором `AShotTracerActor` от дула к точке попадания:
      ribbon-система, заспавненная «на месте», тянула шлейф в сторону.
      `bTracerFlies=false` оставлен для систем, которым носитель не нужен.
- [x] Точка дула ищется по Scene Component с именем/тегом `Muzzle` в юните и во
      ВЛОЖЕННЫХ акторах оружия (оружие — составной Child Actor), затем по сокету
      меша, затем фолбэк на точку LOS.
- [x] Компонент `Muzzle` есть во всех четырёх BP оружия; проверено на живых
      акторах — все пять юнитов резолвят дуло, фолбэк на LOS не срабатывает.
- [x] **Трассеру передаются его user-параметры** (2026-08-03). `NS_BulletTracer`
      сам считает полёт (`CalculateTracerAttributes` → `System.ProjectilePosition`)
      по `User.SpawnPosition` / `User.Hit` / `User.InitialSpeed` /
      `User.TrailDuration`. Без них система рисовала трассер по своим дефолтным
      точкам — отсюда «прилетает сбоку / не виден». Имена параметров и значения —
      в `UUnitVfxDataAsset`; тип (Position или Vector) определяется опросом
      `GetExposedParameters()`, потому что сеттер не того типа молча заводит
      мёртвый параметр.
- [x] Одна трассировка на выстрел кормит и трассер, и импакт: при попадании —
      `ActorLineTraceSingle` по цели (укрытие на линии не перехватывает попавший
      выстрел), при промахе — трейс по миру с физматериалом. Раньше трассер
      обрывался у цели, а искры вспыхивали за ней.
- [x] Импакт ждёт прилёта трассера (таймер на время полёта) и получает
      `User.Hit Normal` / `User.Hit Direction` — эти системы игнорируют поворот
      компонента.
- [x] Шлейф доигрывает после прилёта: актор гасит эмиссию и снимается по
      `LifeSpan = TracerTrailDuration`, а не режет ribbon через `Destroy()`.
- [x] Подача: `TracerSpeed` 7000 см/с (~0.43 с на дальность 3000),
      `TracerTrailDuration` 0.35 с.
- [ ] Отдельный impact-эффект для попадания по бойцу (сейчас общий с бетоном —
      в Niagara Examples нет ассета крови).
- [ ] Разные вспышки под четыре ствола, если хватит времени.

`ImpactBySurface` заполнен (Concrete→`NS_Impact_Concrete`, Metal→`NS_Impact_Metal`),
но пока **не срабатывает**: единственные физматериалы в проекте — ландшафтные
`PM_MW_*`, и у всех шести стоит `SurfaceType3 (Grass)`. Значит любое попадание по
геометрии уходит в `DefaultImpact`. Записи оживут, когда у бетона/металла на
карте появятся свои физматериалы — до тех пор различать поверхности нечем.
