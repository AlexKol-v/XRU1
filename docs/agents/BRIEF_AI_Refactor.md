# Бриф: глубокий рефакторинг тактического AI

Задание для отдельной длинной сессии. Цель — качество решений, а не новые
фичи. Читать вместе с [../08_AI.md](../08_AI.md).

**Главное правило работы: baseline не должен измениться молча.** Каждый шаг
рефакторинга — отдельная сборка и прогон матрицы из §6 `08_AI.md` с
`xru1.AI.LogCombat 1`. Если поведение изменилось, это должно быть осознанным
решением, записанным в `08_AI.md`, а не побочным эффектом переноса кода.

## 1. Что уже сделано (не переделывать)

- `Alert FSM (Patrol/Investigate/Combat)` + utility-оценщики + AP-aware executor.
- `UAIBehaviorProfileDataAsset` — единый ассет тюнинга perception/nav/alert/
  position/target + **поведенческие оси `FAIStyleTuning`**
  (множители веса оценщиков, `FlankWillingness`, `FocusFireBonus`,
  `FinishWoundedWillingness`).
- Назначение профиля по уровню сложности:
  `UTacticsGameInstance::AIProfilesByDifficulty` → `ATacticsGameMode::StartMissionCombat`
  → `AUnitAIController::SetBehaviorProfile`.
- Сведение огня: `UTurnManagerSubsystem::NotifyUnitTargeted/GetTimesTargetedThisTurn`.
- Лимит одновременно атакующих (`MaxAttackersPerTurn`, аналог XCOM `MaxEngagedEnemies`).
- Воспроизводимость: `DecisionSeed` из карты/хода/имени/номера решения, без `GFrameCounter`.
- Диагностика: `xru1.AI.LogCombat`, `xru1.AI.DebugDraw` (цель, точка манёвра,
  скор и причина прямо в мире), категория `LogXRU1AI`, `xru1.Debug.List`.

## 2. Открытые задачи, по приоритету

### P0. `FAIContactMemory` — память о контактах
Сейчас AI знает только «вижу / не вижу». Нужна структура на контроллер:

```
FAIContact { AActor* Target; FVector LastKnownLocation; float LastSeenTurn;
             EContactSource Source; float Confidence; }
```

Источники: собственное зрение, шум выстрела, сообщение союзника.
`Confidence` затухает по числу ходов. `Investigate` идёт к контакту с
наибольшей `Confidence`, а не к единственной `LastKnownThreatLocation`.

Зачем: без памяти враг «забывает» бойца мгновенно и ведёт себя рвано —
самый заметный дефект текущего AI.

### P0. Разбить монолитный `FindCoverPoint`
Сейчас это одна большая функция. Нужен конвейер:
`generation → filters → features → scoring → stable tie-break`.

Требование: **baseline не меняется**. Разбиение делается рефакторингом с
проверкой, что на той же карте и том же seed выбираются те же точки.
Только после этого меняются веса.

### P1. Полные proposals
Перейти от `FAIDecision` c разрозненными полями к
`(Action, Target, Destination, APCost, ExpectedValue)`. Это даёт сравнение
разнородных действий по одной шкале и убирает скрытый приоритет порядка
оценщиков.

### P1. Групповая координация
- Резервации точек: два врага не должны бежать в одно укрытие.
- Общие контакты: увидел один — знает под.
- Бюджет фокуса/атак на сторону за ход (расширение `FocusFireBonus`).

### P2. Честность
Убедиться, что AI нигде не использует информацию, недоступную игроку:
цели берутся только из перцепции и памяти контактов, а не перебором
`GetOpposingUnits`. Сложность меняет стиль и координацию, а не всеведение.

## 3. Как должна ощущаться разница уровней сложности

Заполняется через `FAIStyleTuning` в трёх ассетах
`/Game/XRU1Game/Data/AI/DA_AI_Easy | DA_AI_Medium | DA_AI_Hard`
(единое дерево Data Assets — [../06_CONVENTIONS.md](../06_CONVENTIONS.md) §3).
Их ещё нет; `BP_TacticsGameInstance.AIProfilesByDifficulty` пуст, поэтому
сложность пока меняет только HP/Aim врагов.
Ориентир — XCOM 2, где Rookie/Commander/Legend отличаются не меткостью, а
поведением и числом одновременно вступающих в бой врагов.

| Ось | Easy | Medium | Hard |
|---|---|---|---|
| `MaxAttackersPerTurn` (GameMode) | 4 | 6 | −1 (без лимита) |
| `FocusFireBonus` | 0 | 8 | 25 |
| `FlankWillingness` | 0.3 | 1.0 | 1.6 |
| `FinishWoundedWillingness` | 0.5 | 1.0 | 1.5 |
| `Perception.SightRadius` | 2500 | 2500 | 2800 |
| `EvaluatorWeightMultipliers[UAIEval_HunkerDown]` | 1.5 | 1.0 | 0.6 |
| `EvaluatorWeightMultipliers[UAIEval_AdvanceToCover]` | 0.7 | 1.0 | 1.4 |
| `EvaluatorWeightMultipliers[UAIEval_Overwatch]` | 0.6 | 1.0 | 1.3 |
| `Alert.InvestigateOverwatchChance` | 0.25 | 0.5 | 0.8 |

Читаемый результат: на Easy враги окапываются, дерутся в лоб и наваливаются
максимум вчетвером; на Hard обходят с фланга, сводят огонь на одном бойце,
держат подходы наблюдением и вступают в бой всей группой.

Цифры — стартовая точка, а не догма: после прогона матрицы их правят и
фиксируют в `08_AI.md`.

⚠️ `SightRadius` ниже 2500 не ставить ни на одной сложности: обзор врага не
должен быть меньше дистанции, с которой по нему стреляют, — это в точности
дефект «Причина 1» из [../08_AI.md](../08_AI.md) §3.9 (враг не видел стрелка и
выглядел сломанным). Сложность задаётся стилем, а не слепотой.

## 4. Обязательный порядок работы

1. Прогнать матрицу §6 `08_AI.md` на текущем коде, сохранить логи как baseline.
2. Один пункт из §2 → сборка → та же матрица → сравнение с baseline.
3. Изменение поведения записать в `08_AI.md` с объяснением, почему так лучше.
4. Никаких «заодно поправил веса» внутри рефакторинга структуры.

## 5. Критерии готовности

- [ ] Три последовательных боя на каждой сложности без зависаний хода врага.
- [ ] Враги используют укрытия, не кучкуются в одной точке, не бегают
      туда-обратно между ходами.
- [ ] Решения объяснимы: `xru1.AI.LogCombat 1` даёт читаемую причину каждого
      выбора, `xru1.AI.DebugDraw 1` показывает её в мире.
- [ ] Слепой прогон различает сложности по стилю, а не по числу промахов.
- [ ] Ни одного места, где AI читает позицию невидимого для него бойца.
