## 1. Открытый симптом (главное)

**Атака из приседа (полуукрытие) отрабатывает криво: боец никуда не
поворачивается и стреляет сидя «в пол».**

Симптом появился ПОСЛЕ серии правок презентации 2026-08-03 (список — §4), то
есть это вероятная регрессия, а не исходное поведение. Ни одна из этих правок не
закоммичена: `git status` показывает их в рабочем дереве, откат отдельных файлов
возможен через `git checkout -- <file>`.

Раньше в этой же стойке наблюдались (и были признаны исправленными): выстрел в
позе укрытия, мгновенный доворот, мгновенная посадка после выстрела.

## 2. Как устроена презентация выстрела (коротко)

Владелец — `UTacticalAbility` (`Source/XRU1/Tactics/TacticalAbility.cpp`), общий
для `UGA_Attack` и `UGA_Overwatch`. Blueprint-координаторы —
`BP_GA_Attack` / `BP_GA_Overwatch`, у каждого две ветки презентации.

Порядок фаз зависит от стойки (`EFiringStance`, выбирает
`UTacticsCombatStatics::GetFiringStance`):

| Стойка | Порядок |
|---|---|
| `Open` | доворот стартует вместе с наводкой камеры → latent ждёт его + микропаузу → montage → выстрел |
| `StepOut` | `AI Move To` на огневую точку → доворот → микропауза → montage → выстрел |
| `OverCover` | montage стартует (боец встаёт blend-ом) → доворот по таймеру во время подъёма → пауза → выстрел |

Ключевые точки кода:

- `FaceShotTargetLatent` — BP-узел «Face Shot Target (Latent)» перед montage;
- `NotifyPresentationMontageStarting` — вызывается в момент фактического старта
  montage; для `OverCover` планирует доворот и взводит удержание стойки;
- `ScheduleAimTurnAfterRise` — считает задержку доворота так, чтобы он кончился
  за `AimTurnSettleDelay` до `FireCommit`;
- `EnsureFacingAtCommit` — страховка на самом выстреле: доворачивает мгновенно,
  если отклонение > `AimSnapMaxError`;
- `AUnitBase::SetPresentationStanding` — держит позу `Stand` поверх поз укрытия
  до терминала, чтобы боец не садился сразу после выстрела;
- `WaitShotHoldLatent` — удержание кадра перед возвратом StepOut.

Текущие значения (Class Defaults `BP_GA_Attack` / `BP_GA_Overwatch`):

```
AimTurnRate 420   AimTurnRateMax 900   AimTurnMinAngle 3   AimSnapMaxError 8
AimTurnMaxWait 1.2   AimTurnSettleDelay 0.25   AimTurnRiseDelay 0.35
PreShotCameraSettleDelay 0.4   MinMontageLeadIn 0.25
PostShotHoldDelay 0.7   PostKillHoldDelay 1.8
PreReactionCameraSettleDelay 0.9 (только Overwatch)
```

Монтажи (важно: в обоих лежит анимация стрельбы СТОЯ, отдельного клипа вставания
нет — подъём делает blend-in):

```
AM_Fire_OverCover = MM_Rifle_DryFire | rate 0.8 (0.80 → 1.00 с)
                    blendIn 0.35  blendOut 0.25  FireCommit на 0.50 в клипе = 0.625 с реального времени
AM_Fire_Open      = MF_Rifle_Idle_ADS + MM_Rifle_Fire (аддитивная отдача)
                    blendIn 0.20  blendOut 0.15  FireCommit на 0.24
```

## 3. Как читать лог

| Префикс | Что показывает |
|---|---|
| `[FireAction] Begin` | стойка, montage, дистанция, **отклонение корпуса**, settle |
| `[FireAction] BP запросил план` | BP-ветка дошла до плана и какую стойку получила |
| `[AimTurn]` | планирование/старт/финиш доворота, пауза стабилизации, лимит, страховка |
| `[FireCommit]` | КАДР выстрела внутри montage: позиция/длина, **вес** montage, blendIn/Out, поза |
| `[FireAction] Commit` | попадание и **отклонение корпуса от цели в момент выстрела** |
| `[ShotHold]` | удержание кадра перед возвратом StepOut |
| `[Pose]` | смена позы юнита (0=Stand 1=Moving 2=Crouch 3=High 4=OW 5=Hunker 6=Downed 7=Dead) |
| `[FireAction] Watchdog abort` | зависшая презентация + стойка, montage, montage instance |
| `[VFX] Прогрев профиля` | прогрев Niagara на старте боя (после него компиляций в кадре выстрела быть не должно) |

**Инварианты, которые обязаны выполняться.** Любое нарушение — след бага:

1. `[FireCommit] … вес` ≈ **1.00**. Меньше — выстрел уходит в переходной позе
   (строка сама подсказывает, рано notify или поздно).
2. `[FireAction] Commit … отклонение корпуса от цели` ≈ **0.0°**.
3. Для `OverCover` порядок строк: `BP запросил план` → `пауза стабилизации
   окончена → montage` → `[AimTurn] поверх укрытия — подъём, доворот через X с`
   → `старт доворота (после подъёма из укрытия)` → `[FireCommit]`.
4. `[Pose]` при выстреле поверх укрытия: `2 → 0` (сел → встал) в начале
   презентации и `0 → 2` **после** терминала, а не сразу за `Commit`.
5. Warning `[AimTurn] … на выстреле корпус отвёрнут на N°` появляться не должен.
6. `Compiling System NiagaraSystem` не должно быть в кадре выстрела (только
   рядом со строкой прогрева).

## 4. Что менялось 2026-08-03 (кандидаты на регрессию)

Порядок — от раннего к позднему; каждый пункт проверяем отдельно:

1. Мгновенный `FaceActorTowards` заменён на фазу доворота (`AimTurn`).
2. `bMoving` в `FUnitVisualState` считается по `AUnitAIController::IsFollowingPath()`
   вместо `IsMoving()`; поза сверяется каждый тик в `AUnitBase::Tick`.
3. `FireCommit` notify сдвинут в обоих монтажах (был на кадре 0.00).
4. `PreShotCameraSettleDelay` больше не задерживает старт действия; из ожидания
   вычитается время до `FireCommit` внутри montage; добавлен `MinMontageLeadIn`.
5. Возврат StepOut перенесён за удержание кадра (`WaitShotHoldLatent`).
6. Для `OverCover` доворот перенесён на время подъёма
   (`NotifyPresentationMontageStarting` + `ScheduleAimTurnAfterRise`).
7. **Из обоих BP удалены узлы `Face Actor Towards`**; страховка — только
   `EnsureFacingAtCommit` на самом выстреле (порог 8°).
8. `AM_Fire_OverCover` перетаймлен: blendIn 0.35, blendOut 0.25, rate 0.8,
   notify 0.40 → 0.50. `AM_Fire_Open`: blendIn 0.20, blendOut 0.15, notify 0.24.
9. Введено удержание стойки `SetPresentationStanding` до терминала.
10. Прогрев Niagara на старте боя (`UUnitVfxDataAsset::WarmUpEffects`).

## 5. Гипотезы под симптом «не поворачивается, стреляет сидя в пол»

Проверять по логу, а не по коду. Для каждой указано, чем подтверждается:

1. **Доворот вообще не стартовал.** Нет строки `старт доворота (после подъёма
   из укрытия)` после планирования → таймер `AimTurnRiseTimer` перебит (второй
   выстрел того же юнита, реакция поверх атаки) или транзакция закрылась.
2. **Страховка не сработала.** В `Commit` отклонение большое, но Warning
   `на выстреле корпус отвёрнут` отсутствует → `EnsureFacingAtCommit` не
   вызывается на этом пути (проверить, тот ли `FireCommit` отработал — атаки или
   реакции).
3. **Поворот сделан, но перебит владельцем yaw.** У юнитов
   `bUseControllerRotationYaw = true`; если AI-контроллер в этот момент ведёт
   фокус/маршрут, он возвращает поворот обратно. Признак: отклонение в `Commit`
   ≈ 0°, а визуально боец смотрит мимо.
4. **Стойка на самом деле `Open`.** `[FireAction] Begin … стойка=Open` при
   `[FireCommit] … поза=2` — это НЕ баг сам по себе (укрытие не закрывает цель →
   вставать незачем), но выглядит как «стреляет сидя». Отличать от `OverCover`.
5. **Поза не переключилась на `Stand`.** Нет `[Pose] 2 → 0` в начале
   презентации → `SetPresentationStanding` не взвёлся (стойка не `OverCover`)
   либо позу перебило движение/наблюдение.
6. **Montage не набрал вес.** `[FireCommit] … вес < 1.00` при notify 0.50 —
   значит blend-in не успел (проверить `rate_scale`: `FindFireCommitTime` делит
   время notify на него, и рассогласование ломает весь расчёт).
7. **«В пол» — это направление выстрела, а не поза.** Трассер строится от
   `FiringEyeLocation` замороженного контекста. Если стойка `OverCover`, точка
   должна быть step-up (выше приседа); сверить с `дистанция` и геометрией.

### 7.2. Что нарушено на самом деле

**A. Стойка `Open` у бойца, который физически сидит в укрытии** —
подтверждена гипотеза §5.4, но она НЕ безобидна, как предполагал бриф.

Из 43 атак: `Open` — 35, `OverCover` — 4, `StepOut` — 4. При этом
**18 выстрелов из 43 сделаны в позе укрытия**: `[FireCommit] … поза=2` (присед)
— 10 штук, `поза=3` (прижат к высокой стене) — 8 штук. Из них 15 со стойкой
`Open` и 3 со `StepOut`. Стрелковый montage анимирован СТОЯ, отдельного клипа
стрельбы из приседа нет — отсюда «стреляет сидя в пол, никуда не поворачиваясь».

Причина не в правках §4, а в исходном правиле `GetFiringStance`: стойка
считалась по трейсу укрытия МЕЖДУ стрелком и целью. Боец за стеной, которая
смотрит вбок или назад, получал «укрытия в сторону цели нет» → `Open` →
«стреляй с места, вставать незачем», хотя поза оставалась `Crouch`/`High`.
Гипотеза §5.5 («поза не переключилась на Stand») — следствие того же:
`SetPresentationStanding` взводится только для `OverCover`.

**B. Две истины на вопрос «могу ли я выстрелить»** — в §5 брифа этого пункта
не было, но в логе он есть:

```
[Targeting] 0 → 1 unit=BP_Unit_Assault_C_0        ← игрок вошёл в прицел
[Camera] Кадр выстрела: Assault_C_0 → Marauder_C_12, dist2D=334
[FireAction] Reject at activation: из замороженной позиции нет линии огня
```
— дважды подряд. И зеркально у AI:
```
[FireAction] Reject at activation: … shooter=Marauder_C_12 target=Assault_C_0
[AI] Marauder_C_12: атака не активировалась — цель заблокирована до конца хода
[AI] Marauder_C_12 закончил ход БЕЗ ДЕЙСТВИЙ: … видимая цель=Assault_C_0
```

Доступность цели решал `HasLineOfSight` (вопрос ВИДИМОСТИ: более широкий набор
точек, включая корпусную точку стрелка, которой нет среди огневых позиций), а
активация — линию огня из ЗАМОРОЖЕННОЙ точки выстрела, выбранной
`GetFiringStance`. Наборы точек не совпадали → HUD показывал шанс, выстрел
отклонялся.

### 7.3. Что сделано

1. `UTacticsCombatStatics::FindFiringSolution` — единый перебор «есть ли выстрел
   и откуда». `GetFiringStance` стал его обёрткой; `UGA_Attack::GetTargetStatus`
   спрашивает его вместо `HasLineOfSight`. Дубль линии огня в
   `UGA_Overwatch::TryReactTo` убран (`CanTargetActor` уже её спрашивает).
   `HasLineOfSight` остаётся только для ОБНАРУЖЕНИЯ.
2. `UTacticsCombatStatics::IsUnitInCoverPose` — стойка для решения из центра
   решается позой бойца (`FUnitVisualState`, тот же срез, что читает ABP), а не
   направлением его стены: в позе укрытия → `OverCover` (встал → довернулся →
   выстрелил → сел).
3. `SetPresentationStanding(true)` распространён на стойку `StepOut`.

Ассеты не правились: `FireMontageOverCover = AM_Fire_OverCover` уже стоит у всех
пяти `BP_Unit_*` (включая `BP_Unit_Marauder`), `FireMontageStepOut` пуст и
штатно падает на `FireMontageOpen`.

### 7.4. Найдено аудитом правки и тоже исправлено

1. **Решение и валидация могли разъехаться на краях укрытия.** Перебор проверял
   позиции по набору точек цели, построенному ОДИН раз от центра глаз стрелка,
   а `IsFrozenFireCommitValid` строил его заново от ВЫБРАННОЙ точки. Пики цели
   зависят от направления на стрелка, поэтому у StepOut наборы различались.
   Теперь позиция принимается ровно тем предикатом, которым проверяет commit
   (`HasLineOfSightFromFrozenOrigin`) — согласованность по построению.
2. **Сломалась бы симметрия Ф5.** У цели в наборе есть корпусная точка, у
   стрелка среди огневых позиций её не было: «стрелок.глаза → враг.корпус»
   проходило, обратное — нет. Корпусная точка стрелка добавлена последней в
   список огневых позиций.
3. **`[ReactionAction] Reject invalid frozen solution` после отыгранной
   анимации.** `NotifyPresentationMontageStarting` теперь возвращает `bool` и
   проверяет решение ПЕРЕД стартом montage: протухло — ветка обрывается,
   транзакция отменяется, боец не вскидывается впустую. Выстрел наблюдения не
   сгорает (лимит растёт только после `FireCommit`).
4. **Штраф Squadsight не применялся ни разу.** Висел на `!HasLineOfSight`, а
   `ComputeEffectiveAim` зовётся только после `CanTargetActor`, который требует
   геометрию всегда. Переведён на `UGA_Attack::IsSquadsightShot` («цель дальше
   собственного обзора») — единое определение для допуска цели, метки транзакции
   и штрафа, ровно как в GDD §5.4 (−10).
5. **`IsUnitInCoverPose` врал во время презентации.** Была ветка «поднят
   презентацией ⇒ всё равно считаем в укрытии»; убрана — функция BlueprintPure
   и обязана отвечать по факту позы. Переиграть стойку это не может: она
   заморожена в контексте на Begin.

⚠️ Числа боя изменились: штраф Squadsight −10 теперь реально работает у снайпера
на дистанции свыше 2500 см. Это приведение кода к GDD, а не новое правило.

### 7.5. Второй цикл аудита (код + блюпринты)

6. **Перф-регрессия в моей же правке.** Точная проверка позиции
   (`HasLineOfSightFromFrozenOrigin`) строит пик-набор ЦЕЛИ заново на каждую
   позицию стрелка — до пяти построений с nav-проекциями там, где раньше было
   одно. Добавлено «быстрое ДА»: свип до глаз/корпуса цели — достаточное условие
   (обе точки входят в любой exposed-набор), поэтому полный набор строится
   только когда цель реально прячется. Плюс мемоизация трейса своего укрытия
   (спрашивался до трёх раз за вызов).
7. **Отказ до montage ломал StepOut.** Боец там УЖЕ вышел из укрытия, а возврат
   живёт в BP-ветке за монтажом (`Return from Step Out` → `Set Actor Location` +
   `Hug Cover`); `AbortPresentation` его не отыгрывает — боец остался бы стоять
   в поле. Проверка перед montage теперь пропускает `StepOut`: там отказ уже не
   бесплатен и решение по-прежнему проверяется на `FireCommit`.
8. **Ассет: подъём вставал за 0.20 с вместо 0.35.** Переходы
   `ABP_Solider.Locomotion` `CrouchCover → Idle` и `HighCover → Idle` стояли на
   0.20 при blend-in монтажа 0.35 и `AimTurnRiseDelay` 0.35. Montage играет
   поверх позы, поэтому виден быстрейший из двух — подъём рвался. Обе
   длительности выставлены в 0.35 (правка верифицирована обратным чтением
   графа), посадка оставлена 0.20.

**Проверка блюпринтов.** `Face Actor Towards` — 0 узлов в обоих BP (как и
