# Бриф сессии: аудит незакоммиченных изменений и коммит

Отдельная сессия. Задача — **проверить всё, что накопилось в рабочей копии, и
разложить по осмысленным коммитам**. Аудит первичен: коммит фиксирует уже
проверенное, а не наоборот.

---

историю потом не прочитать.

## 2. Порядок: сначала аудит, потом коммит

### Шаг 1. Проект собирается

```bash
./Build-XRU1.ps1 -StopEditor
```

Редактор перед сборкой закрыть, предварительно сохранив пакеты
(`save_dirty_packages` через MCP — в редакторе могут быть чужие несохранённые
правки). После успешной сборки редактор поднять обратно. Не собирается —
дальше не идти, чинить.

### Шаг 2. Аудит diff по каждому изменённому C++ файлу

Читать `git diff` целиком, а не по верхам. Искать конкретное:

- **отладочный мусор**: временные `UE_LOG`, закомментированный код, `TODO`
  без задачи, тестовые константы;
- **нарушения конвенций проекта** (`06_CONVENTIONS.md`): комментарии на русском,
  `UPROPERTY` для дизайнерских параметров, GE-компоненты через
  `CreateDefaultSubobject`, отсутствие жёстких путей `/Game/...` в C++;
- **логику, противоречащую документации**: если код делает не то, что написано
  в доках, это находка — записать, не «чинить по дороге»;
- **следы незавершённой работы**: функции, которые никто не вызывает; поля,
  добавленные и не прочитанные;
- **опасные места**: разыменование без проверки, работа с `TWeakObjectPtr` без
  `IsValid`, подписки без отписки в `EndPlay`.

Найденное разделить на «блокирует коммит» и «отдельная задача в backlog».
Блокирующее — исправить сразу и пересобрать.

**Чем искать быстрее.** Для «кто вызывает эту функцию» и «есть ли у поля хоть
один потребитель» — не `Grep` по всему дереву, а **`codebase-memory` MCP**
(проект `D-Unrial_Projects-XRU1`): `search_code` по коду и докам сразу,
`search_graph`/`trace_path` по связям. Индекс живой — видит рабочую копию, а не
последний коммит. В `search_code` для `foo|bar` обязателен `regex=true`, иначе
`|` матчится буквально. Мёртвый код («функция, которую никто не зовёт») ищется
именно так — по нулевому `in_degree` в графе.

### Шаг 3. Аудит ассетов

`.uasset` и `.umap` в diff не читаются глазами — проверять иначе:

- новые ассеты лежат в `/Game/XRU1Game/**` по правилу дерева Data Assets
  (`06_CONVENTIONS.md` §3), а не в корне `Content`;
- `.umap` изменения ожидаемы (расстановка миссии) и не содержат случайно
  перетащенных акторов — сверить список акторов через редактор;
- бинарники идут через **LFS**: проверить `.gitattributes` и что новые
  `.uasset` подхвачены (`git lfs status`);
- ничего из `Saved/`, `Intermediate/`, `Content/UnrealClaude/` не попало в
  индекс (эти пути в `.gitignore`, но проверить).

покажется странным. Автотесты `XRU1.AI.*` должны быть зелёными ДО коммита:


### Шаг 5. Что НЕ делать

- **Не пушить.** `git push` с LFS-бинарниками на медленном канале висит долго —
  это работа пользователя, ему дать готовую команду.
- Не трогать ветку: если работа идёт на `main`, спросить, нужна ли ветка, и
  дождаться ответа.
- Не «причёсывать» код, не связанный с текущими изменениями: рефакторинг
  соседних функций в этот коммит не входит.
- Не откатывать чужие правки. Сессия AI завершена, её файлы коммитятся на общих
  основаниях — но **не «причёсывать» их по дороге**: там много намеренно
  неочевидных решений (обратный знак `RelocateBias`, штраф за возврат на прошлую
  позицию, отступление без бонуса за линию огня). Каждое объяснено в комментарии
  и в `08_AI.md`; выглядит странно — сначала читать обоснование.

## 3. Отчёт по итогам

Дать пользователю:

1. **Список находок** — что нашёл аудит, с разделением «исправлено сразу» /
   «вынесено в backlog» / «требует его решения».
2. **Список коммитов** — что во что попало, одной строкой каждый.
3. **Готовую команду пуша** — в отдельном блоке, чтобы он запустил сам.
4. Прямой ответ на вопрос «можно ли на этом состоянии делать сборку демо» —
   да/нет и почему.
